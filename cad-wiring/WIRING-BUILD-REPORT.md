# End-to-End Wire → Contact → Connector

**2026-07-30 · ToolCRIB · Zoo wiring benchmark, build 1**

Brief: show one wire connection end to end — wire, pin, into the connector —
**with a contact present only where a wire exists, and no contact where there
isn't one.** Foundation for later wiring bundles and harnesses for cars and GA
aircraft.

**Status: requirement met.** Proven by editing only the wire list and
re-rendering.

---

## 1. The headline result

`harness-data.kcl` is the only file you edit. It is a list of records:

```kcl
export wireList = [
  { cav = 1, awg = 20, colour = "#c62828", sig = "28V PWR IN" },
  { cav = 4, awg = 24, colour = "#1565c0", sig = "RS-232 TX" },
  ...
]
```

Cavities are generated by mapping over **all nine**. Contacts, conductors and
insulation are generated by mapping over **the wire list only**.

| Render | Wire list | Result |
|---|---|---|
| `mating-face-straight.jpg` | 6 wires: 1,2,4,5,7,9 | 6 bright pins, **3 dark open bores** at 3, 6, 8 |
| `mating-face-fully-loaded.jpg` | 9 wires | 9 pins, **no open bores** |

Nothing changed between those two renders except records in the data file.
No geometry was edited.

## 2. What "end to end" contains

Along +Z, mating face at z = 0:

| Feature | Span | Notes |
|---|---|---|
| Engaging pin | −0.150 → 0.030 | protrudes through the mating face |
| Contact barrel | 0.020 → 0.290 | seated in the insulator cavity |
| Crimp barrel | 0.270 → 0.470 | grips the conductor behind the insulator |
| Exposed conductor | 0.460 → 0.650 | the stripped section, visible |
| Wire insulation | 0.650 → 1.900 | coloured per the data record |

Conductor and insulation radii are **driven by AWG** through `condR()` and
`insulR()`, so a 20 AWG power wire is visibly fatter than a 24 AWG signal wire
in the render.

## 3. Data provenance

Retrieved via NotebookLM from the **Garmin G500/G600 TXi, GI 275, GTN 6XX/7XX,
GNC 215, GFC 500 and GTX 3X5 installation manuals**, plus **AC 43.13-1B**.

### CONFIRMED

- **Connectors in service:** GEA 24(B) uses 9-pin (J241), 25 (J242), 37 (J243),
  50-pin (J244) standard D-sub. HD variants in use: 26, 44, 62, 78 pin.
  A 9-way was chosen for this build because it is real hardware here and small
  enough to read in a render.
- **Contact sizes:** size 20 accepts 20–24 AWG (Garmin 336-00024-00 pin,
  336-00022-02 socket); size 22 accepts 20–24 AWG; size 22D accepts 22–28 AWG
  (M39029/58-360).
- **Gender is set by the LRU, not by convention.** Unit-side male → harness
  carries sockets (GDU, GI 275, GAD 43). Unit-side female → harness carries
  pins (GCU 485, GDC 72, GSU 75, GRS 79, GEA 110, GTN, GNC 215).
  *There is no global rule about which side is "hot".*
- **Wire gauge:** GFC 500 — signal min 24 AWG, load-carrying min 22 AWG.
  Power/ground 20 AWG on 28 V, 18 AWG on 14 V. Config modules always 28 AWG.
  Runs over 20 ft must be sized per AC 43.13-1B Ch. 11.
- **Insulation:** MIL-W-22759/16, /18, /34 unshielded; MIL-C-27500 shielded.
  **/18 is recommended for HD connectors** — thinner wall suits HD spacing.
- **Bundle:** support at ≤24 in with MS21919 clamps; ≥½ in clearance from
  moving controls; never route through fuel bays.
- **Shield:** drain pigtail ≤3.0 in; unshielded portion at the backshell
  ≤2.5 in; backshell stack-up 8-32 screw → split lock → flat washer → ring
  terminal; max 2 ring terminals per hole.
- **Strain relief caution:** place the **smooth/convex** side across the
  harness. The grooved/concave side will damage wires.

### NOT PRESENT — every geometric dimension here is an assumption

The manuals state outright that **contact pitch, centre-to-centre spacing and
shell mechanical dimensions are not documented.** So `pitch = 0.109`,
`rowGap = 0.112`, cavity and contact radii, and the flange envelope are all
flagged `[A]` in `parameters.kcl`.

Also absent: maximum wires per bundle, general bundle bend radius (only the
GMU 44B pigtail's 1.5 in is given), and voltage-drop sizing curves.

## 4. New engine finding

**`subtract()` has the same class of limit as `union()`.**

```
engine: The Zoo engine cannot handle this 3D subtraction yet. Please report this as an issue
```

Triggered by subtracting three cutters from a plate — two circular jackscrew
holes plus one rectangular window — where the window would have turned the
plate into a frame. Dropping the window fixed it; the two holes subtract fine.

This matters because previous reports (`cad-an-fittings/assembly/ENGINE-LIMITS.md`)
documented union limits only. Subtraction is affected too, and again the
trigger looks like **topology**, not operand count: nine cavity cutters
subtract from the insulator in a single call without complaint, while three
cutters fail when one creates a frame.

Consistent with the earlier conclusion that operand *kind and resulting
topology*, not *count*, is the determining factor.

### Language capabilities confirmed working

All verified before building:

- `if / else` as an **expression**, including nested chains
- user-defined functions with `fn(@arg)` and `export fn`
- **arrays of records** with member access (`w.cav`, `w.awg`)
- `map(list, f = fn(@x) { ... })` returning solids
- comparison operators on record fields

That combination is what makes data-driven geometry possible. Without `map`
over records this brief could not have been met.

## 6. ADDENDUM — dimensions verified against manufacturer data

The build originally flagged every geometric dimension `[A]`, because the
Garmin manuals state outright that contact pitch and shell dimensions are not
documented. Those have now been resolved against published manufacturer data.

**Result: the assumed pitch and row spacing were correct.**

| Dimension | Was | Datasheet | Verdict |
|---|---|---|---|
| Contact pitch in a row | 0.109 `[A]` | **.109 (2.77)** dim E | ✅ correct |
| Row centre-to-centre | 0.112 `[A]` | **.112 (2.84)** dim F | ✅ correct |
| Jackscrew hole c-c | 0.984 `[A]` | **.984 (25.00)** dim A | ✅ correct |
| Jackscrew hole dia | 0.124 `[A]` | **.125 (3.18)** dim H | ✅ correct |
| Contact hole dia | 0.062 `[A]` | **.045 (1.14)** dim I | ❌ **was 38% oversize** |
| Shell body envelope | 1.100 × 0.400 `[A]` | **.777 × .440** cutout C × E | ❌ **was too wide** |
| D-shell side taper | not modelled | **10°** | ❌ **shell was a rectangle** |

Two of those were real errors. The insulator was too wide, the cavities too
large, and the shell had no D-profile at all — the polarising feature that
makes a D-sub a D-sub. All three are now corrected from the datasheet, and the
insulator is built as a proper trapezoid derived from cutout width, height and
the 10° taper.

### Also captured for later HD work

| Spec | Value |
|---|---|
| HD pitch, 15 / 26 / 44 way | **.090 (2.29)** |
| HD pitch, 62 / 78 way | **.095 (2.41)** |
| HD row offset | **.078 (1.98)** |
| HD contact hole dia | **.040 (1.02)** |

Those matter because the Garmin fleet is mostly high density — GDU P2/P3/P4
are 44 / 62 / 78 way, and the GI 275 is 78 way.

### Sourcing notes

- **[Spectrum Control, "D-Sub Board & Panel Cutouts"](https://www.spectrumcontrol.com/asset/d-sub-board-panel-cutouts.pdf)**
  — the useful one. Complete board-layout and panel-cutout tables for shell
  sizes 9/15/25/37/50 plus all HD variants, in inches and mm.
- **[NorComp](https://www.norcomp.net/products/dsub-connectors/1)** —
  independently corroborates 2.76 mm contact spacing and 2.84 mm row spacing.
- **[NASA NEPP MIL-DTL-24308 page](https://nepp.nasa.gov/npsl/connectors/311p409/24308pn.htm)**
  — confirms the standard-density / size-20-crimp-contact classification but
  carries no dimensional table.
- **Amphenol CDN datasheets returned HTTP 403** to automated fetch; their data
  could not be used. Noted so nobody wastes time retrying.

The MIL spec itself is **MIL-DTL-24308**. Series designations align with the
pitch: *Series 109* is standard density (.109), *Series 90* is high density
(.090) — a useful mnemonic, and consistent with the measured values above.

## 7. ADDENDUM — mating half and connected pair

Added `receptacle.kcl` (socket side) and `main-mated.kcl` (both halves).

### Gender assignment is not arbitrary

[C] The Garmin manuals are explicit: **contact gender is set by the LRU chassis,
not by any electrical convention.** Unit-side male means the harness carries
sockets (GDU, GI 275, GAD 43). Unit-side female means the harness carries pins
(GCU 485, GDC 72, GSU 75, GRS 79, GEA 110, GTN, GNC 215). There is no global
rule about which side is "hot".

This model uses **harness = pins (plug)**, **equipment = sockets (receptacle)**,
matching the GTN / GNC / GSU family.

### The numbering mirror — the detail that bites people

Viewed from its own mating face, a receptacle's cavity numbering runs
**opposite** to the plug's. That mirror is exactly what makes pin N meet
socket N when the halves come together.

Two ways to model it:

1. Model the receptacle in its own face-view frame with mirrored numbering,
   then rotate it 180° about Y to face the plug.
2. Model it directly in the mated orientation, so cavity N has the **same
   world X** on both halves.

**Option 2 was used** — fewer transforms, less to get wrong, and alignment is
explicit in the code rather than emerging from a rotation. `receptacle.kcl`
carries a comment stating that its `cavX(n)` should be read as *world X of
cavity n*, not as position on the receptacle's own face. Anyone extending this
to a real pin map needs to know which convention the file is using.

### Contact-present rule holds on both halves

Sockets are generated by mapping over `wireList`, same as pins. Cavities 3, 6
and 8 are empty bores on the plug **and** the receptacle. Add a wire and a pin
*and* a socket appear together.

### Correct placement, demonstrated

Equipment-side pigtails use the **same colour per cavity** as the harness side.
In `mated-placement-check.jpg` (front elevation) the colour order above and
below the interface is identical — cavity N carries the same signal through the
joint. That is the visual check.

| Render | Shows |
|---|---|
| `mated-separated.jpg` | halves drawn apart, `matingGap = 0.55` |
| `mated-connected.jpg` | fully mated, `matingGap = 0` |
| `mated-placement-check.jpg` | front elevation, colour order matches across the joint |

`matingGap` is a single parameter: 0 seats the 0.150 pins fully inside the
0.170 socket bores; any positive value draws the halves apart.

## 8. ADDENDUM — the three gaps, closed

### 8.1 Flanges and jackscrews — the joint is now fastened hardware

Both halves gained **flange ears** carrying the verified jackscrew holes:
`.984` centre-to-centre, `.125` dia — both `[CD]` from the Spectrum Control
table. Two **4-40 jackscrews** now pass through the plug ear and the receptacle
ear. 4-40 UNC is the D-sub screw-lock thread per Amphenol and NorComp product
data.

Screw positions derive from `jackScrewX` — **the same value that cut both
holes** — so a screw cannot land anywhere except in its own hole. Change the
shell size and holes and screws move together.

New file: `jackscrew.kcl`, modelled at local origin, placed by `main-mated.kcl`.

### 8.2 "Mated" is no longer a free parameter

Previously `matingGap` was a number I chose, and choosing it wrong silently
produced a wrong assembly. Now **both halves are modelled with their flange
face at local z = 0**, so mating is the geometric consequence of placing the
receptacle at the origin. There is nothing to set.

`separation` remains, but only to draw the halves apart for inspection, and it
defaults to `0`.

**This is still not a mate solver.** The Zoo MCP exposes none. What changed is
that the constraint is now expressed as shared derived geometry plus a screw
that visibly occupies both holes — a wrong assembly becomes visible rather than
plausible. That is weaker than a solver and is not claimed to be equivalent.

### 8.3 Contacts are now revolved profiles

`revolve()` works, which makes a genuine contact possible. Each contact is a
**single revolved body** with:

- a blunt tip and **chamfered lead-in**
- a **mating pin section** at the engaging diameter
- a **retention shoulder** stepped to clear the cavity bore
- a **crimp barrel** stepped larger, sitting behind the insulator

Sockets use the same approach, then subtract a bore sized to accept the pin.
Previously both were stacked cylinders.

**Revolve syntax gotcha:** the axis must lie in the sketch plane and is named
in the sketch's **local** frame. On an `XZ` sketch, revolving about world Z
requires `axis = Y`. Using `axis = Z` fails with *"Invalid axis of revolution.
Axis of revolution must lie in the plane."*

### 8.4 New engine/tooling finding — imports render everything

Importing a module executes it and renders **all** of its geometry, not only
the exports you reference. A view file that imported `plug.kcl` to show just
the hardware still rendered the wires, because they exist in the imported
module.

**Consequence:** you cannot compose a partial view by importing and
cherry-picking. A trimmed view must be self-contained, or the source module
must be split so the unwanted geometry lives elsewhere. A `view-joint.kcl`
written on the wrong assumption was deleted rather than left in place claiming
something it did not do.

## 9. ADDENDUM — 78-way HD connector and backshell

New files: `parameters-hd78.kcl`, `harness-78-data.kcl`, `main-hd78.kcl`,
`view-hd78-face.kcl`.

This is the connector on the **GI 275 (J2751)** and the **GDU P4** — [C] from
the Garmin manuals. 78 cavities, **22 populated**, which is the sparse case a
real installation actually has.

### 9.1 The pitch nearly went in wrong — geometry caught it

Amphenol states HD-78 is a **three row** layout, so 26/26/26. The Spectrum
Control HD page prints **both** `.095 (2.41)` and `.082 (2.08)` near the 62 and
78 drawings.

Taking `.095` for the 78 gives a contact span of **25 × .095 = 2.375"**. Shell
size 4's panel cutout is **2.190"** wide. **It cannot fit.**

Taking `.082` gives **25 × .082 = 2.050"**, which fits with margin. So `.095`
belongs to the HD-62 drawing beside it, and HD-78 is `.082`.

**A dimensional sanity check disproved the first reading.** Worth doing every
time two candidate numbers sit near each other on a datasheet page.

Final HD-78 field: 3 rows × 26, **X pitch .082**, **row gap .095**, middle row
**staggered .041** (half pitch — that stagger is what makes HD density work),
**contact hole .040**, shell size 4 with **2.406 jackscrew span**.

### 9.2 Backshell

| Part | Detail |
|---|---|
| Housing | lofted taper, connector throat → cable exit, hollowed to `bsWallT` |
| Shield ground block | 4 × **8-32** tapped holes for ring terminals |
| Strain relief clamp | bar with two screw holes, **smooth face toward the harness** |
| Harness bundle | gathered wires exiting the strain relief |

Confirmed rules recorded in the file headers and honoured where geometric:

- [C] **CAUTION: the smooth/convex side of the strain relief goes across the
  harness.** The grooved/concave side will damage wires. The bar is modelled
  smooth-face-down for exactly that reason.
- [C] Wrap silicone fusion tape **A-A-59163** where the clamp meets the housing.
- [C] Shield drain pigtail **≤ 3.0 in**; unshielded length at the backshell
  **≤ 2.5 in**.
- [C] Ring terminal stack: **8-32 screw → split lock → flat washer → ring
  terminal(s)**, max **2 terminals per tapped hole**, max 2 wires per terminal
  (3 if space-constrained).
- [C] Garmin uses proprietary shield-ground-adapter backshells. **MS3057 and
  MIL-C-85049 are NOT referenced** in these manuals — only Garmin part numbers.

Individual wires now terminate **inside** the housing and gather into a bundle
rather than passing through the wall, which is both correct and what makes this
extensible to real harnesses.

### 9.3 New engine finding — subtraction fails when the cutter splits the body

`subtract()` was rejected on the strain relief clamp. Cause, once found, was
unambiguous: **the screw hole diameter exceeded the bar's thickness**, so the
cut would have severed it into three pieces.

```
engine: The Zoo engine cannot handle this 3D subtraction yet.
```

This is the most **diagnosable** instance of the boolean limits so far, and it
supports the running conclusion that the trigger is **resulting topology**, not
operand count:

| Case | Cutters | Result |
|---|---|---|
| 78 cavity bores from one insulator | 78 | ✅ works |
| 2 jackscrew holes from a flange ear | 2 | ✅ works |
| 2 holes wider than the bar they cut | 2 | ❌ rejected — would split the body |
| 2 holes + a window that makes a frame | 3 | ❌ rejected — frame topology |

**Rule of thumb: if the cut would disconnect or frame the body, expect
rejection.** Cutter count is irrelevant — 78 is fine.

`srScrewR` and `srClampT` now carry a comment stating the constraint so the
trap is not re-sprung.

## 10. ADDENDUM — full harness run, two connectors and a bundle

New files: `harness-route-data.kcl`, `main-harness-run.kcl`.

### 10.1 The data model changed, and this is the important part

Up to now the model was driven by a **wire list** — "these cavities have wires".
A real harness is not that. It is a list of **ROUTES**: a conductor leaves a
cavity at one end and lands on a **different** cavity at the other.

```kcl
{ from = 1,  to = 41, awg = 22, colour = "#c62828", sig = "28V PWR" }
{ from = 44, to = 12, awg = 22, colour = "#212121", sig = "SIG GND" }
```

Contacts are generated **per end** from this table: a pin at `hd78X(from)` on
connector A and at `hd78X(to)` on connector B, independently. Delete a route
and both contacts disappear together — correct, because a conductor that does
not exist cannot be terminated at either end.

This is the foundation the brief was aiming at. Bundles and multi-branch
harnesses are extensions of a route table, not of a wire list.

### 10.2 Geometry

- Two 78-way HD connectors, panel-mounted orientation, 5.2 in apart
- Contacts and coloured wire stubs per route, at both ends
- **Breakout boots** — lofted transitions, wide enough at the base to cover
  the contact field, necking to the bundle diameter
- **Swept bundle** rising from A, crossing, and dropping into B, with two
  exactly-90° tangential arcs

A first attempt had the wire stubs simply stop in mid-air at bundle height —
they fanned across the connector width while the bundle was 0.33 in across, so
nothing joined up. The lofted boot is what actually gathers them.

### 10.3 Corner rounding is now the family standard

`fillet()` with `getNextAdjacentEdge()` on tagged profile lines. Radii are
named parameters: `insulCornerR`, `earCornerR`, `hoodCornerR`, `barCornerR`.

Useful ordering discovery: **a fillet survives a later subtract.** The
insulator is filleted first and then has all 78 cavities cut into it, and the
engine accepts that. Given how fragile the booleans have been elsewhere, that
was not a safe assumption to make without testing.

## 11. Honest gaps

- **Pins only, no sockets.** Gender is confirmed to be LRU-driven, so a real
  harness needs both. Not modelled yet.
- **Wires run straight.** No bundle, no sweep, no bend radius enforcement. The
  24 in support rule and ½ in control clearance are recorded but not geometric.
- **No backshell or strain relief**, despite having the confirmed data for both.
- ~~No shell D-profile~~ — **FIXED**, see §6. Insulator is now a true D-profile
  trapezoid from the datasheet cutout and 10° taper. The outer flange plate is
  still a plain rectangle.
- ~~Pitch is unverified~~ — **RESOLVED**, see §6. Verified correct against
  manufacturer data.
- ~~Contact is a stepped cylinder~~ — **FIXED**, see §8.3. Revolved profile
  with chamfer, shoulder and crimp barrel.
- ~~No flange or jackscrews; mating is positional~~ — **FIXED**, see §8.1–8.2.
  Ears, 4-40 jackscrews, and mating determined by geometry rather than a
  chosen number. Still not a solver-enforced constraint.
- **Flange overall size is still `[A]`.** The datasheet gives jackscrew spacing
  and the cutout, not the outer flange envelope. 1.213 × 0.494 remains assumed.
- **Insulator thickness is still `[A]`.** Not present in a cutout drawing.
- **No backshell.** The confirmed strain-relief data — smooth side across the
  harness, silicone fusion tape A-A-59163, shield pigtail ≤3.0 in, unshielded
  length ≤2.5 in, the 8-32 ring-terminal stack-up — is recorded but not
  modelled. That is the obvious next piece.
- **Contact profile dimensions are `[A]`.** The shape is now correct in kind;
  the individual radii and steps are proportioned, not sourced. A real
  M39029 contact drawing would settle them.
- **Jackscrew thread is not modelled** as a helix, only as a plain shank.
